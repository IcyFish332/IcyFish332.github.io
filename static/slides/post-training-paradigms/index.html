00

预备知识：KL 散度

KL 散度的非对称性是理解 SFT 与 RL 行为差异的基础。用简单分布 Q 拟合复杂分布 P 时，优化方向不同会导致截然不同的结果。

KL Primer

Forward KL：Mean-Seeking / Mode-Covering

定义

minQ DKL(P || Q) = minQ ∑ P(x) log P(x)/Q(x)

期望在真实分布 P 上计算。

关键行为

  • P(x) > 0 时：Q(x) 必须也 > 0，否则 log Q(x) → −∞，KL 爆炸
  • P(x) ≈ 0 时：该项对总和贡献极小 — Q 在 P 不存在的地方可以随意分配概率

行为特性

Mean-Seeking / Zero-Avoiding

为了不遗漏 P 的任何峰值，Q 倾向于变得宽而平坦，覆盖 P 所有非零区域。

若 P 是多峰分布，Q 会用一个大方差的单峰罩住所有峰 — 宁可错杀一千，不可放过一个。

在后训练中

SFT = 最小化 Forward KL — 模型必须对训练数据中所有出现的 token 分配概率，即使这意味着牺牲原有分布的模式。

Ref: KL进阶: Forward KL、Reverse KL、KL估计与应用

KL Primer

Reverse KL：Mode-Seeking / Zero-Forcing

定义

minQ DKL(Q || P) = minQ ∑ Q(x) log Q(x)/P(x)

期望在模型分布 Q 上计算。

关键行为

  • P(x) ≈ 0 时：若 Q(x) > 0，log P(x) → −∞，KL 爆炸 — Q 绝不能在 P 不存在的地方分配概率
  • P(x) > 0 但 Q(x) ≈ 0 时：该项贡献极小 — Q 可以选择性忽略 P 的某些模式

行为特性

Mode-Seeking / Zero-Forcing

Q 倾向于找到 P 的单一最高峰并精确拟合，完全忽略其他峰。

宁缺毋滥 — 生成质量高但多样性低，可能引发 mode collapse。

在后训练中

RL ≈ 最小化 Reverse KL — 模型只在自己有把握的区域分配概率，不会被迫覆盖远离当前策略的分布区域。OPD 同样使用 Reverse KL。

KL Primer

对比总结：覆盖 vs. 聚焦

Forward KL   DKL(P || Q) Reverse KL   DKL(Q || P)
期望基于真实分布 P（面向数据）模型分布 Q（面向模型）
拟合策略覆盖 — 宽而平坦（Mean-Seeking）聚焦 — 窄而精确（Mode-Seeking）
典型方法SFT（最大似然估计）RL / OPD / OPSD
风险过于平滑，牺牲旧模式Mode collapse，多样性不足

选择的本质

Forward KL 要求模型对所有观察到的数据都要有良好的解释（面向数据）；Reverse KL 要求模型生成的任何样本都是逼真的（面向模型）。

这种根本差异使得两者在后训练中扮演截然不同的角色 — 后面我们会看到，SFT 的灾难性遗忘和 RL 的抗遗忘性都可以从这个视角得到解释。

在后训练语境下

SFT = Forward KL — 模型必须覆盖训练数据的所有 token，可能以牺牲原有能力为代价

RL ≈ Reverse KL — 模型只在自己的高概率区域更新，隐式保护已有分布

OPD / OPSD = Reverse KL — 但教师信号的质量决定了"聚焦"的方向是否正确

Ref: KL进阶: Forward KL、Reverse KL、KL估计与应用

我们要回答的核心问题

  • 为什么 SFT 便宜高效，但存在不可逾越的天花板？
  • 为什么 RL 昂贵缓慢，却更抗遗忘、泛化更好？
  • 为什么 OPD 看起来像蒸馏，却继承了 RL 的许多好处？
  • 为什么 OPSD 同样是 on-policy，却容易在 100 步内崩溃？

这些问题的答案，都可以从 KL 散度的方向、数据的 on/off-policy 属性、以及梯度的几何特性 三个视角得到统一的解释。

01

分布视角与标准 Pipeline

语言模型是序列上的分布，后训练就是重塑这个分布。标准 pipeline 的 SFT → RL 排序不是惯例，而是有数学原因的。

Pipeline

SFT → RL 的 Tipping Point

为什么先 SFT，后 RL？

  • 当前性能远低于教师时：SFT bits 极其便宜 — 从有能力的来源学习你没有的能力
  • 当前性能接近教师时：边际 SFT 样本不再 informative — 学生自己的 rollout 开始产生教师没见过的新策略
  • 越过 tipping point 后，rollout compute 花在 RL 上比花在更多 SFT 上更值

关键区别

  • SFT 的采样分布在数据集构建时就已固定 — 改进不会回馈到数据
  • RL 的采样分布是当前策略 — 改进复合累积，天花板由 verifier 而非教师决定
02

Supervised Fine-Tuning

用外部数据集做 cross-entropy 训练。目标分布在训练前就已固定，天花板由教师/数据决定。

SFT

SFT：拉向一个固定的外部分布

  • 数据集在训练前就已存在（人写 / 强模型生成）
  • Cross-entropy 训练 = 最小化 forward KL
  • 模型被拉向数据分布，与起始分布无关
  • 天花板由教师/数据决定 — 学生最多达到教师水平

SFT 的本质：对每个 token 施加均匀的、密集的监督信号，不区分任务关键 token 与风格 token。

SFT

SFT 的梯度特性：稠密、有偏、但分散

  • 每个 token 都有 one-hot label，梯度密度极高
  • 梯度均值 非零 — 指向数据分布的方向，构成 constructive interference
  • 但数据本身多样，偏置分散在许多方向 — 模型温和地漂向数据流形

为什么 SFT 不会"爆炸"？

因为大多数 SFT 更新只是在强化模型已经大致知道的东西，很少有 token 要求模型把接近零的概率拉到很高。

SFT

SFT 的天花板与灾难性遗忘

天花板问题

  • 采样分布在数据集构建时就已固定
  • 模型变强后，数据不会跟着变 — 边际收益递减
  • Rejection-sampled SFT 把曲线上移，但不改变形状

灾难性遗忘

  • Forward KL 的 mode-covering 行为：为覆盖新模式，可能牺牲旧模式
  • Diao et al.：SFT 数据含大量低概率 + 低熵 token — 模型高度自信但被迫拟合冲突标签

Ref: Diao et al., Understanding the Dark Side of LLMs' Fine-Tuning Data (2026)

SFT

教师的选择：Same-family vs. Cross-family

此处"教师"泛指 SFT 训练数据的来源 — 可以是更强的模型生成的 completions，也可以是人类标注。Brown 在原文中将其统一称为 teacher SFT，以便与 OPD / OPSD 的教师概念拉齐到同一框架下。

Same-family Teacher

  • Tokenizer 一致、训练 recipe 一致
  • 教师输出的分布结构接近学生自然产出
  • SFT 信号主要关于能力差距，而非风格差异
  • Per-token logprobs 直接可比

e.g. Qwen3-32B → Qwen3-8B

Cross-family Teacher

  • Tokenizer 不匹配 — 重新分词时信息丢失
  • Recipe 不匹配 — 学生被迫学习教师的风格瑕疵
  • 大量 SFT bits 消耗在学表面形式，而非推理能力
  • Soft-target distillation 几乎不可行

e.g. GPT-4o → Llama-3

这个区分至关重要：On-policy distillation 基本只在 same-family 设定下可用。

03

Reinforcement Learning

模型从自身采样，由 reward 指引方向。没有固定的目标分布，天花板由验证器决定。

RL

RL：沿期望奖励最大方向移动

  • 模型从自身 on-policy 采样 — 改进会回馈到下一轮采样分布
  • Reward function 评分，policy gradient 更新
  • 没有一个任意的外部分布拉扯模型
  • 复合效应：改进累积，天花板由 verifier 而非教师决定

RLVR vs. RLHF

  • RLVR：可验证奖励，低偏差 — 可以大胆放松 KL 约束
  • RLHF：reward model 不完美，高偏差 — 需要 trust-region 约束
RL

RL 的梯度特性：稀疏、无偏、破坏性干涉

  • Outcome reward 是 O(1) bits per episode — 表面看信息极度稀疏
  • 每个 token 的 advantage 大多是噪声 — 它们恰好在同一条轨迹上，不是因果负责
  • 大 batch 平均后，噪声方向相互抵消
  • 存活下来的是与 reward 真正相关的微小一致性成分

RL 的稀疏性不是纯粹的缺陷 — 它是无偏估计器的代价。每步移动很小，但方向可信。

04

为什么 RL 遗忘更少？

KL 方向、数据依赖正则化、稀疏参数更新 — 多种解释各有道理，但 on-policy 数据才是核心承重件。

RL vs. SFT

为什么 RL 遗忘更少？

解释一：KL 方向不同

  • SFT = forward KL — mode-covering，可能牺牲旧模式学新任务
  • RL ≈ reverse KL — mode-seeking，保守地在已有模式上改进

问题：即使去掉显式 KL 惩罚，RL 仍然不怎么遗忘

解释二：数据依赖正则化

  • RL 中 reward variance 高的组获得更小的更新
  • SFT 对每个 token 均匀施压，不管是否任务关键
  • RL 更新只修改小子网络（稀疏但满秩），SFT 更新更冗余

Ref: Chen et al., Reinforcement Learning as Reverse KL Minimization (2025) · Mukherjee et al., RL Finetunes Small Subnetworks (2025) · Lai et al., Data-Dependent Regularization in RL (2025)

RL vs. SFT

核心解释：On-Policy 数据是承重件

不是 RL 算法本身特殊，也不是显式 KL 惩罚在做主要工作。
On-policy 采样才是真正让你在提升能力的同时不炸掉 KL 预算的东西。

Shenfeld et al. 的直觉

  • REINFORCE + binary reward ≈ rejection sampling
  • 最优策略 = 所有 completion reward = 1 的策略
  • 因为在当前策略上采样，目标自动是距当前策略最近的最优策略
  • 每个 timestep 的更新方向都隐式约束了 KL 预算

SFT 的目标分布可以离起始分布任意远；RL 的目标在每一步都紧贴当前策略。

Ref: Shenfeld et al., On-Policy Learning Implicitly Regularizes Against Forgetting (2025)

05

On-Policy Distillation

学生自己采样，教师逐 token 打分。兼具 RL 的复合效应和蒸馏的信号密度。

OPD

OPD：两个世界之间的甜蜜点

  • 学生 on-policy 采样 — 继承 RL 的复合效应
  • 教师 per-token reverse KL 评分 — 信号密度远高于 RL
  • 教师只需对学生的 tokens 做 prefill — 比生成便宜得多
  • 计算效率：在 AIME 级 benchmark 上比 RL 快 9-30x

为什么实际上限高于 SFT-RS？

  • SFT/SFT-RS 在教师的 state 分布上训练，但在学生的 state 分布上评估
  • 长 rollout 上的 exposure bias 逐步积累
  • OPD 在学生自己的 rollout 上训练，gap 不会打开

Framing 注意：OPD 不等于"全面优于 RL"。更准确的说法是 — OPD 是 moderate compute + same-family teacher 下的 compute-optimal shortcut，能更快到达教师水平；但 RL 的天花板由 verifier 决定，在极限 compute 下可能更高。

OPD

实验：不同教师的 OPD — 惊人发现

实验设计

Minimal Code Editing 任务：给模型一个有 bug 的函数，要求修复 bug 且不改动其他部分。分别用 SFT 和 RL 训教师，再用两个教师做 OPD 蒸馏。

这个任务能同时测两件事：泛化（在不同 corruption 类型上评估）和遗忘（在 LiveCodeBench 上检测通用代码能力退化）。

三个意外

  • SFT 教师和 RL 教师的 OPD 学生几乎一样好
  • 两个 OPD 学生都略微超越了 RL 教师
  • 即使 SFT 教师有严重遗忘，其 OPD 学生的遗忘远小于教师本身

数据来源（on-policy 采样）比教师质量更重要。这意味着我们可以用 SFT "过拟合"一个专家模型，再用 OPD 把能力转移出来。

Ref: Agarwal et al., On-Policy Distillation of Language Models (2023) · Ross et al., DAgger: A Reduction of Imitation Learning (2010)

OPD

学生为何能超越教师？

假说一：On-policy state coverage

教师在学生的错误前缀上给建议，而非在教师自己的前缀上 — 监督更有针对性。

假说二：分布塑形 ≠ 奖励最大化

KL matching 传递了风格、不确定性、推理结构等信息，可能在不复制教师 greedy 行为的情况下改善采样分布。

假说三：Entropy collapse

OPD 的 entropy 下降远比 RL 剧烈 — reverse KL 的 mode-seeking 导致模型在新能力上高度集中。

06

自蒸馏：SDFT & OPSD

没有 same-family 教师时，用自己当教师 + privileged information。两种实例化：
SDFT — 教师看到 expert demonstration（分布偏移较温和）
OPSD — 教师看到 ground-truth answer（分布偏移更剧烈，梯度集中是致命风险）

OPSD

OPSD：Pivot Token 主导梯度

问题机制

  • 学生和教师是同一模型，教师多了 ground-truth answer 做前缀
  • 大多数 token 两者概率接近 — KL ≈ 0
  • 关键 pivot token：学生 p=0.01，教师 p=0.6
  • Per-token KL ≈ log(0.6/0.01) ≈ 4.1 — 比普通 token 大 ~100 倍

后果

  • RL 的噪声可以抵消，SFT 的偏置分散在许多 token 上
  • OPSD 两者都没有 — 一个集中的拉力，不被平均
  • 不加 per-token KL clipping → ~100 步内崩溃

Ref: Zhao et al., OPSD: On-Policy Self-Distillation for LLMs (2026)

OPSD

Per-token KL 分析：Style Token 的陷阱

  • Zhao et al. 对 OPSD 做了 per-token KL 分解
  • 发现 style/pivot token（如 "wait""alright"）的 KL 显著高于 math token（"exponent""logarithm"）
  • 如果对这些不重要的 token 更新过于激进 → 模型坍塌
  • 解决方案：per-token pointwise KL clipping

OPSD 的处境类似 RLHF 而非 RLVR：教师信号的偏差更高，必须用 clipping / trust-region 防止过度优化错误方向。

Ref: Zhao et al., OPSD: On-Policy Self-Distillation for LLMs (2026)

07

统一框架

梯度特性的三轴分类（sparse/dense, biased/unbiased, concentrated/diffuse），以及将所有方法纳入同一个 meta-algorithm。

Unified View

梯度特性统一分析：两个基本轴

轴一：Sparse vs. Dense

每个 token 是否都得到独立的学习信号？

  • RL：稀疏 — 整条轨迹只有一个 outcome reward，广播到所有 token。大多数 token 的 advantage 只是噪声（恰好在同一条轨迹上，不是因果负责）
  • SFT / OPD / OPSD：稠密 — 每个 token 都有独立的监督信号（one-hot label 或 teacher logprob），无需广播

轴二：Biased vs. Unbiased

梯度的期望方向是否指向一个固定目标？

  • RL：无偏 — 梯度期望只沿与 reward 相关的方向非零。noise 互相抵消（destructive interference），存活下来的是微小但可信的信号
  • SFT / OPD / OPSD：有偏 — 梯度期望始终指向目标分布，noise 不会抵消而是叠加（constructive interference）

SFT、OPD、OPSD 都在右上角（dense + biased），但它们的行为差异巨大 — 仅靠这两个轴不足以区分。我们需要第三个轴。

Unified View

第三轴：Concentration — 偏置集中在哪里？

SFT：偏置分散（Diffuse）

数据本身多样，偏置方向分散在许多 token 上。大多数更新只是在强化模型已经大致知道的东西，很少要求把接近零的概率拉到很高。所以 SFT 容错性好 — 数据有些脏、学习率有些偏都不会崩。

Same-family OPD：偏置同样分散

教师与学生分布结构接近（同 tokenizer/recipe），per-token KL 普遍较小且均匀。继承了 SFT 的分散性。

OPSD：偏置高度集中（Concentrated）

教师看到了答案后，少数 pivot token 的 KL 爆炸式增长（~100x），梯度被这几个 token 主导。RL 的噪声可以抵消，SFT 的偏置足够分散 — OPSD 两者都没有。这就是为什么不加 clipping 会在 ~100 步内崩溃。

Punchline：OPSD 是唯一同时具备 dense + biased + concentrated 的方法。这就是为什么它需要显式防御（per-token KL clipping、固定教师为初始策略）而其他方法不需要。下一步的方向是：寻找 KL 天然分散的教师，而不是靠 clipping 来压制集中的教师。

Meta-Algorithm

统一框架：三个旋钮，所有方法都是特例

Brown 将所有后训练方法统一为一个 token-level policy gradient，由三个旋钮控制：

  • $\alpha \in [0,1]$ — 采样分布的 on-policy 程度
    0 = 纯 off-policy（固定数据集），1 = 纯 on-policy（当前策略采样）
  • $\lambda \in [0,1]$ — per-token advantage 的来源混合
    1 = 纯教师 KL 信号，0 = 纯 outcome reward
  • $\pi_T$ — 教师策略的选择
    哪个模型、什么 conditioning、什么 privileged info
Meta-Algorithm

这个框架的正确读法

它解释了什么？

  • 为什么 OPSD 和 OPD dial settings 完全相同（$\alpha=1, \lambda=1$）— 唯一的区别是 $\pi_T$ 的选择
  • 为什么 SFT 可以被看作退化教师的蒸馏：$\pi_T = \delta_{y_{\text{data}}}$，即 one-hot label
  • 为什么 RL 是"无教师"：$\lambda=0$，per-token 信号退化为广播 outcome reward

Caveat：这个参数化是说明性的，不是在建议真的在 $(\alpha, \lambda)$ 的中间地带插值。Brown 明确指出：SFT / RL / OPD 这几个"干净的角落"之所以好用，恰恰是因为不需要 importance-sampling 修正。

真正重要的问题不是调这三个旋钮，而是：选定 KL 预算 $\beta$ 后，为当前学生找到最优的教师。

产业实践与未来方向

Expert merging 正成为后训练的最终阶段。Pareto 最优教师指出了下一代算法的形状。

Industry Practice

产业实践：Expert Training + OPD Merging

完整 Pipeline

Pretrain → SFT → RL/Self-distill → OPD merge

  • GLM5、DeepSeek V4：用 OPD 合并专家能力，最终 checkpoint 不再经过 RL
  • Math/Code 任务偏好 RL 训练的专家
  • Creative writing / knowledge-heavy 任务偏好蒸馏类方法

值得注意

  • RL 域：merged 学生几乎总是超越教师
  • Self-distill 域：学生略逊于教师
  • 趋势：expert merging 正成为后训练最后阶段的标准范式

Ref: MiMo-V2 Flash Technical Report (2026) · GLM-5 Technical Report (2026) · DeepSeek V4 (2026)

Pareto 最优教师与未来方向

最优教师问题

我们想要的教师策略应该：在每步更新中最大化 reward 改善，同时受 KL 约束保持稳定。

$$\max_{\pi_T} \; \mathbb{E}_{x,\, \hat{y} \sim \pi_T}\!\left[ R(\hat{y}) - R(\pi_\theta) \right] - \beta \cdot \mathbb{E}_x\!\left[ D_{\text{KL}}\!\left(\pi_T(\cdot|x) \,\|\, \pi_\theta(\cdot|x)\right) \right]$$

理想算法的形状

  • 蒸馏的密度
  • RL 的无偏性
  • 两者共有的 on-policy 性质

Core Takeaways

  • On-policy 数据是承重件 — 不是 RL 特殊，是 on-policy 采样提供隐式 KL 正则化

  • 梯度特性决定稳定性 — RL 稀疏无偏，SFT 稠密分散，OPSD 稠密集中（危险）
